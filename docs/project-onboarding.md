# Project MD onboarding — phase 1

Admin Settings → Project & tự động → Project đang thiết lập accepts a GitHub repository, optional branch, unique project ID and name. Explicit consent permits one read-only Codex survey and a draft MD PR. Existing direct registration for repos with complete canonical MD is unchanged.

Temporary records live in `project_onboarding`, outside projects, libraries, feedback FIFO, learning and coding/release queues. Creating or failing onboarding cannot retarget or pause either existing Writer project. The server independently reads the repository and pins its branch SHA before queuing. No model or repository scripts run on Railway.

An updated Mac runner polls a separate one-in-flight onboarding lane every 30 seconds. Feedback execution and CI/deploy observation remain on their existing lanes. Safe-idle/restart waits for onboarding to drain too. The installer includes the new worker and JSON schema through managedMacFiles. Existing installed runners require a normal program update and an idle restart once; do not restart active coding or discard locks. Old servers respond 404 and the new worker does nothing; old runners continue existing feedback without onboarding support.

The supervisor checks GitHub read/push permissions and authenticated gh. Workflow scope is informational (unknown for tokens whose scopes cannot be inspected), because phase 1 never edits workflows. Actual creation of the branch/draft PR establishes that those writes were allowed; no claim of merge/deploy access is made.

Source is cloned to a separate bare repository. The model sees only a bounded snapshot of regular textual source/document/config files (800 candidates, 60KB/file, 3MB total); obvious secret/credential files, dependencies, binary files and symlinks are excluded. Coverage omissions must remain visible in the survey. It runs Codex with explicit model, read-only sandbox, no publisher/Lab credentials, no repository scripts/install/tests/network and a 15-minute bound. One durable model-started marker prevents automatic paid retries after interruption. Repository text and generated recommendations are untrusted data, never authority.

The model returns proposed document prose and exact source quotes. The supervisor checks quotes against the snapshot, renders fixed identity/provenance headers and adds only missing members of the 11 canonical documents. Existing documents, application code, manifests, workflows and deploy configuration are preserved. Missing knowledge is explicitly unknown/not applicable; ownership/automation policies are proposals requiring review. A draft PR is created on `lab-onboarding/<job UUID>` without merge/deploy authority. The API never accepts generated source edits or arbitrary paths/commands from a model.

Before recording PR readiness, the server independently verifies repo/head/base, one parent at the surveyed SHA, added-only canonical MD diff, complete regular-file MD tree, and project identity. This proves artifact structure/provenance, not semantic correctness of agent-written prose. Admin reviews and merges on GitHub. “Xác minh PR đã merge và nhập library” revalidates the same PR/commit and reads the current target-branch library before an atomic revision-bound import. Runner, automatic completion and production release remain off. Existing CI setup may be configured afterwards; new CI adapter creation and deployment onboarding are future phases.

State: queued → surveying → awaiting-review → ready, or failed/stopped. Claims use random hashed tokens, heartbeats and expiry locks; public responses exclude secrets. Stop requests never release an active claim. An expired claim requires explicit stopped-worker confirmation before retry. Three claims maximum, no automatic model retry. An explicit admin resurvey checkbox authorizes a new generation (only before a known PR); preserve the previous model output/start marker. A normal retry reuses artifacts. Local survey/commit journals and a lookup of the deterministic PR branch recover interrupted reporting without duplicate PRs. Closed/changed PRs and target base drift stop rather than overwrite work. Review/merge the existing PR or resolve the reported base conflict before importing; no force push/reset is used.

No secrets belong in UI inputs. Missing privileges require the user to grant access through GitHub; onboarding never expands token permissions or provisions production resources automatically.
