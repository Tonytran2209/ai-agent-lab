# Bounded feedback investigation

Feedback keeps the original text and provisional Luna classification. Codex reads pinned source and complete relevant canonical MD. Missing root-cause knowledge is technical work, not a product decision.

The survey remains read-only. Existing targeted offline non-browser tests may run if feasible; dependencies are not installed and write/network restrictions are not relaxed. New regression fixtures and implementation run only after an exact-scope executable plan is validated. Synthetic fixtures verify contracts, never prove a production reproduction.

`impact.checkpoints` records investigation, product-decision, access or external-evidence with a reason and attempted checks. Every explicit question must match a typed checkpoint. Genuine user blockers require attempted checks. Legacy questions remain blocking; no text heuristic deletes them.

A successful initial plan containing a technical checkpoint, or an external-evidence checkpoint with no attempted checks, gets one diagnostic follow-up on the same pinned checkout and lease. The first call has six minutes; both calls together have ten minutes. The follow-up has the original feedback, MD, source map and previous plan, and investigates relevant layers before choosing exact source/test/MD paths. Failure stops without an automatic model retry. One survey allowance covers this bounded pair; it does not call the Lab classification API again.

A technical question still unresolved after this pass remains blocked and displays “Điều tra chưa hoàn tất”, without a mandatory user reply form. External/product/access blockers display the minimum question. Findings and checkpoint details are in Nhật ký, with agent-attested labeling. Up to three previous plans retain pinned commit/library and assessment provenance.

After execution stops for a scope mismatch, opted-in impact-auto low/medium requests may get one fresh survey under the existing three-attempt/daily budgets. No edits beyond scope are permitted. A new plan re-enters policy, source-evidence, exact-scope, traceability, CI, documentation, release-consent and per-project FIFO gates. High risk and genuine missing product decisions still require review. The automatic replan is not repeated indefinitely, and expired leases are not reclaimed.

Old blocked requests are not silently rewritten. An explicit resurvey uses the updated worker and preserves the previous plan. A read-only diagnosis may remain inconclusive; it cannot guarantee every feedback will produce a deployable change.

Mixed unit/browser plans are reconciled separately: exact-head GitHub browser records prove browser criteria; passed same-head unit checks and inspections retain their original agent-reported provenance. A changed repair head requires refreshed local reports. The original implementation summary is retained.
